# 固定灰度权重初始化

本模块只估计并冻结每台相机的 RGB 灰度权重。没有新增 ESIKF 状态，没有修改曝光参数及其初值、协方差、过程噪声，也没有修改外参、历史参考曝光、SCPS 或视觉地图维护策略。

## 开关和生效时间

```yaml
vio:
  color_gray_init_en: false
```

三个多相机示例配置均默认关闭。关闭时不创建初始化快照或工作线程，灰度继续使用原来的 OpenCV `BGR2GRAY` 路径。

启用要求：直接法前端、切平面图像块、至少两台相机、可用 LiDAR 平面，以及可用的 SIFT。构建时优先检测 `cv::SIFT`，不支持时检测旧版 `cv::xfeatures2d::SIFT`。启用时还会实际创建检测器，识别旧 contrib 库虽能链接但未启用实现的情况。依赖不可用时打印红色加粗原因，主流程继续使用原灰度。现有 `visual_geom_filter_voxel_size` 必须与 LiDAR 地图的 `max_voxel_size` 一致，否则不启动校准，也不擅自覆盖旧参数。

IMU 初始化完成后，颜色初始化在正常 VIO 调用中检查数据是否就绪；不跳过视觉帧、不等待后台拟合完成，也没有固定的 2 秒超时或 3 次尝试上限。LiDAR 和 VIO 继续使用原灰度运行。主线程最多每秒尝试构建一份独立快照，耗时的匹配和拟合在单个后台 worker 中完成；worker 忙时不构建新快照，没有 RGB 等待队列。构建快照仍有主线程复制图像和几何筛选的开销，后台计算也会共享 CPU，尚未实测耗时。

全部相机通过检查后，主线程在下一次视觉处理开始、转换该组相机图像之前一次性安装权重；仅后续转换的图像和新生成的观测使用新权重。成功日志和各相机权重为绿色加粗。样本不足或拟合未通过时继续原灰度，并在至少一秒后尝试新快照；数据等待原因最多每五秒输出一次。依赖或配置不支持、启动异常或结果安装失败会终止校准并明确报告，主流程仍继续。

按用户要求，不清空地图、不重建或回算旧参考、不新增观测版本筛选。旧观测继续按原有选择与维护规则存在，因此切换后可能出现新灰度图像与旧灰度参考的匹配；原曝光标量不能一般性消除通道权重改变造成的差异。此过渡效果未经运行验证。权重只安装一次，曝光状态、初值、协方差和过程噪声均保持原流程。

进程退出时通知 worker 取消，并安全回收线程。正在执行的单次 OpenCV 调用不能强制中断；取消标志在调用之间检查。

## 估计的对象

相机 0 保持原 OpenCV 灰度定义，作为相对颜色响应的基准。对于待校准相机，用一组同步图像中的对应 RGB 样本拟合：

\[
 y_i \simeq \boldsymbol\beta_c^T\mathbf{RGB}_{c,i},\qquad
 \mathbf w_c = \frac{\boldsymbol\beta_c}{\mathbf1^T\boldsymbol\beta_c}.
\]

`beta` 的整体幅度只用于拟合时容纳不同曝光。函数只输出归一化后的 `w`，不保存额外增益，不把这个幅度写入原曝光状态。每个在线相机曝光参数仍按原有流程估计。

拟合采用按区域平衡的 Huber IRLS。整个物理区域划入训练或验证集合；同一次拟合中，两侧原图支撑重叠的区域不会重复计入，不能把同一个小块的像素拆成伪独立验证。检查包括颜色矩阵的秩、目标灰度变化、非负权重和独立区域误差；负系数不会被裁剪后冒充有效结果。

验证基线是“默认 RGB 权重 + 训练区域拟合的临时标量”，而不是强迫原始灰度值直接相等。若默认权重已获得足够支持且没有明确改善，则保留原 OpenCV 转换。满足无噪声线性关系、采样正确且颜色满秩时，拟合可以恢复真实通道比例；真实 RGB 含噪、非线性 ISP 或模型不适用时，没有无偏保证。

当前工程验收条件包括至少 6 个独立区域、64 个样本，验证 RMSE 不高于 5 个灰度级，以及通常至少 0.5 灰度级且 5% 的基线改善。无噪声精确恢复使用单独的数值容差判断。这些阈值尚未经用户数据集调优，不是统计置信度保证。

## 对应和取样

1. 复用当前相机模型、状态中的几何变换、LiDAR 点与已有平面关联，复制候选平面的几何值。worker 不引用实时地图或状态。
2. 在候选平面投影附近的实际输入图像中提取 SIFT。图像上下文至少补到 `96×96`，至多 `320×320`，并限制在图像边界内；图像本身小于 96 时使用可用范围。取消原来平面投影宽高至少 48 像素的入口门槛。只扩大图像裁剪，不扩大或重新构建三维平面。关键点检测掩膜不再额外腐蚀四圈；描述子可读取周围图像，关键点中心则必须通过原平面的精确亚像素支撑检查。筛选时同步保留对应描述子行。
3. 将匹配坐标映射到局部切平面，以平面诱导单应为几何初值，正反方向分别估计完整的残余仿射变换。至少需要 6 对空间去重后的匹配；按空间顺序每 3 对留出 1 对，最低配置恰好是 4 对拟合、2 对验证，更多匹配仍参与。两侧拟合点和 RANSAC 内点都检查二维分布是否退化；每个方向至少 4 个拟合内点，至少 4 个双向一致的训练支撑点。留出点不进入拟合。这个修正只用于初始化取样，不更新全局外参。
4. 保留原来的双向原图误差、留出平均误差、残余形变、支撑凸包面积/宽度和正反向一致性限制。在验证支撑凸包的面积质心附近建立 `16×16` 共同切平面网格；沿用两侧原图像素足迹确定的采样步长，而不是将整个凸包缩放进 16×16。凸包外及平面支撑外的网格点仍无效。局部投影变化检查覆盖实际网格四角。原图缩小时的预滤波保持不变；后续局部颜色均值和方差使用 `5×5`、sigma=1.0 的共同网格高斯窗口，掩膜腐蚀与边界遍历也使用同一窗口尺寸。
5. 有效对应交给权重拟合。相机可以沿成功的共视连接逐个校准；每台新相机的一次拟合只使用一台已经校准的父相机，不混合不同父相机的亮度尺度。必须全部成功才安装。

平面的 `radius_` 来自点分布协方差，候选支撑复用已有的半径倍数规则；它不是真实表面边界或无遮挡证明。局部滤波是保守近似，不是相机 PSF 标定。SIFT 也不保证鱼眼与针孔之间每个区域都能匹配成功。

小网格不再沿用旧大网格的隔 3 点取色，而是遍历所有满足完整 `5×5` 支撑的中心，最多 `12×12=144` 个候选均值。窗口外的填充值、原图平面外的滤波像素和不满足原始通道范围的像素均不会成为有效样本。邻近均值可重叠，但保留同一物理区域 ID；区域权重平衡和按整个区域划分颜色训练/验证的流程不变，不能把 144 个均值当成 144 个独立区域。

6 对匹配和 5×5 统计窗口是此次小区域适配的工程设置，不是已验证的最优阈值。相较旧版，几何验证冗余和局部平滑程度减少；全局颜色拟合的至少 6 区域、64 样本、颜色秩和验证误差要求没有降低。边界投影失败或缺少有效特征、空间支撑的区域仍会被拒绝。

## 存储与正常运行

初始化期间只保留当前 worker 的独立 BGR 快照、相机模型副本和有限平面候选。没有为历史 Feature 或 Observation 增加 RGB 字段。初始化结束后，仅保留每相机三个权重及转换查找表；正常图像依然输出 `CV_8UC1`，已有切平面采样、warp、残差和参考维护继续使用灰度。

当前上限为 24 个候选平面、每对相机最多处理 12 个区域、每个原图裁剪不超过 `320×320`、每相机 SIFT 输入总面积不超过 `12×320×320`、每裁剪最多 500 个特征。16×16 网格每区域最多产生 144 个候选均值，每对相机当前最多 `12×144=1728` 个，代码另保留原有 4096 样本硬上限。关键点和描述子在同一快照的共视连接之间复用，不保存 SIFT 金字塔。灰度查找表约 6 KiB/相机；实际耗时和峰值内存尚未测量。

运行日志使用 `[ Color Gray Init ]` 前缀，给出 SIFT 后端、数据等待原因、后台尝试、成功权重、共视父相机、区域/样本数、验证误差和基线误差，或者具体拒绝原因。日志中的误差包含拟合阶段的临时亮度比例，不能解释为安装权重后的原始灰度已绝对相等。

## 分阶段诊断日志

开启 `vio.color_gray_init_en` 后，每次后台尝试完成时，主线程集中打印一组加粗日志：青色为计数，黄色为拒绝原因。关闭该开关时不收集、不打印这些诊断；没有新增日志开关。小区域版本会先输出 `small-region settings: feature_context_min=96 matches_min=6 train_min=4 holdout_min=2 grid=16x16 color_kernel=5x5 color_stride=1`，便于确认运行的是更新后的程序。

每个实际尝试过的相机连接单独输出，例如 `camera1->camera0` 表示用相机 1 的 RGB 拟合相机 0 的灰度。多相机中即使同一相机换过父相机，之前的尝试也会保留在本次日志里。

所有阶段统一使用 **通过数/进入数**；`0/0` 表示尚未进入该阶段。计数单位在行首给出，不能把匹配点数、区域数与颜色样本数混为一谈。

| 单位 | 阶段 | 含义 |
| --- | --- | --- |
| regions | `seed`, `roi` | 平面种子有效；两侧均能构建裁剪区域 |
| regions | `sift_src`, `sift_dst` | 两侧特征检查分别通过；源侧失败时仍沿用原流程跳过目标侧提取 |
| regions | `independent` | 与本次已产出颜色样本的区域没有原图支撑重叠 |
| regions | `geometry` | 匹配数量、双向残余仿射、留出验证和支撑分布全部通过 |
| regions | `rgb_region` | 该区域至少产出一个有效颜色样本 |
| matches | `ratio`, `mutual`, `tangent`, `unique` | 正向比值、反向匹配与比值、切平面映射、空间去重 |
| pixels | `grid` | 网格位置通过几何、双向一致性、滤波边界及原图掩膜检查 |
| samples | `color` | 逐个遍历小网格内部中心，候选颜色样本通过完整 5×5 支撑、灰度/RGB 范围和方差检查 |
| pairs | `fit` | 该相机连接的权重拟合验收通过；不是“已经开始数值求解”的含义 |

`keypoints_max(src/dst)` 和 `unique_max_per_region` 是该连接内单区域的最大数量；匹配行上的计数则是各区域之和。特征可来自同一快照的缓存，`sift_src/dst` 统计区域检查次数，不表示实际调用 SIFT 的次数。

拒绝行记录每个条目的**第一个失败条件**和数量。例如下面是格式示意，并非实际运行结果：

```text
[ Color Gray Init ] camera1->camera0 geometry reject (regions): holdout_error_gt_2px=5 unique_matches_lt_6=3
[ Color Gray Init ] camera1->camera0 fit reject (pairs): insufficient_samples=1
```

这表示 5 个区域因几何留出点误差超过原有 2 像素门限被拒绝，另有 3 个区域在去重后不足 6 个匹配。最终拟合样本不足只是下游结果。其他常见原因：

- `source_empty_plane_projection` / `target_empty_plane_projection`：对应一侧的平面投影为空；旧 `crop_lt_48px` 门槛已移除。
- `empty_sift_mask` / `supported_keypoints_lt_6`：有效特征掩膜为空或通过平面中心检查的关键点不足。
- `forward_*` / `reverse_*`：对应方向的残余仿射估计或检查失败。
- `forward_training_points_degenerate` / `reverse_training_points_degenerate`：拟合点的二维分布退化，不能确定完整仿射；RANSAC 内点还有对应的 `*_ransac_inliers_degenerate` 检查。
- `invalid_hull_centroid` / `jacobian_variation_gt_20pct`：支撑凸包质心无效或取样窗口内投影变化超过原限制；不再要求凸包两边都能填满 16 个采样点。
- `source_raw_mask` / `target_raw_mask`：原图掩膜不满足取样要求；掩膜同时包含平面支撑、原始通道范围和滤波邻域限制，不能仅凭这个计数断定是饱和。
- `invalid_5x5_support`：颜色均值使用的完整滤波邻域不全有效。
- `*_variance_gt_36_or_nan`：局部方差不满足原有检查。
- `scan_stop=pair_region_budget_12` / `camera_sift_pixel_budget`：处理预算耗尽，不是匹配阈值拒绝。
- `scan_stop=candidate_list_exhausted`：本次候选已遍历完，不表示所有候选通过。

若没有可用的验证误差，打印 `n/a`，避免把默认的 `inf` 误读成实际测得的误差。发生取消或异常时，未完成的计数标记为 `interrupted`；不会为了补齐计数继续执行算法。

## 现有其他日志开关

这些参数修改后需要重新启动节点；当前代码在初始化时读取，不是运行时动态开关。本次未修改配置。

| YAML 参数（均在 `vio:` 下） | 可以关闭的输出 | 注意 |
| --- | --- | --- |
| `visual_map_manage_log_en: false` | `[ VIO Map Manage ]` | 不关闭地图管理本身 |
| `visual_geom_filter_log_en: false` | `[ VIO Geom Filter ]` | 不关闭几何筛选本身 |
| `usage_stats_en: false` | 使用/观测统计表 | 跨相机 patch 使用统计也停止；若还需观察它，保留 `true`，将 `usage_stats_window` 从 100 增至 500 可降低打印频率 |

仓库中的 `mid360_mei_multi_cam.yaml` 已将上面三个布尔开关关闭；`HILTI22_multi_cam.yaml` 和 `M2DGR_multi_cam.yaml` 则开启。运行机器实际加载的配置可能不同。

每条 IMU/图像接收 `ROS_INFO`、每帧 `LIO Mapping Time` / `VIO Time` 表和体素滑窗的 `[DEBUG]` 输出，目前没有独立 YAML 日志开关。`VIO Ref Build` 在 `visual_ref_post_ekf_build_en` 开启时仍会输出，不能仅靠 `visual_geom_filter_log_en: false` 消除。在线标定统计也没有独立的日志开关。不应通过关闭滑窗、参考构建或在线标定等算法功能来消除输出。ROS 日志等级只控制 ROS 日志调用，不能关闭这些直接使用 `printf` / `std::cout` 的表格和消息。

## 本次验证边界

按用户要求，本地没有编译、没有运行测试或数据集。已添加独立数学和灰度转换测试源文件并接入 `tests/CMakeLists.txt`，它们尚未执行。当前交付是代码实现与静态审查，不代表已通过目标 ROS/OpenCV 环境编译，也不代表已确认初始化成功率、耗时或里程计精度收益。

固定线性权重不能保证任意异源相机的颜色响应可统一，也不能补偿后续任意白平衡/色调映射变化。当前没有在安装时重新核验最新帧的白平衡；即使变化发生在异步初始化期间，快照上验证的权重也可能已经不适合最新图像。纯标量变化仍由原曝光模型处理；原系统历史参考的亮度基准若不一致，本模块不会回头重标定它们。初始化拟合误差也不能代替实际 8 位灰度、视觉残差和轨迹精度的端到端验证。
