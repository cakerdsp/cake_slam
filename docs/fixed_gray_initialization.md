# 固定灰度权重初始化

本模块只估计并冻结每台相机的 RGB 灰度权重。没有新增 ESIKF 状态，没有修改曝光参数及其初值、协方差、过程噪声，也没有修改外参、历史参考曝光、SCPS 或视觉地图维护策略。

## 开关和生效时间

```yaml
vio:
  color_gray_init_en: false
```

三个多相机示例配置均默认关闭。关闭时不创建初始化快照或工作线程，灰度继续使用原来的 OpenCV `BGR2GRAY` 路径。

启用要求：直接法前端、切平面图像块、至少两台相机、可用 LiDAR 平面，以及可用的 SIFT。构建时优先检测 `cv::SIFT`，不支持时检测旧版 `cv::xfeatures2d::SIFT`。启用时还会实际创建检测器，识别旧 contrib 库虽能链接但未启用实现的情况。依赖不可用时打印红色加粗原因，主流程继续使用原灰度。现有 `visual_geom_filter_voxel_size` 必须与 LiDAR 地图的 `max_voxel_size` 一致，否则不启动校准，也不擅自覆盖旧参数。

IMU 初始化完成后，颜色初始化在正常 VIO 调用中检查数据是否就绪；不跳过视觉帧、不等待后台拟合完成，也没有固定的 2 秒超时或 3 次尝试上限。LiDAR 和 VIO 继续使用原灰度运行。主线程最多每秒尝试构建一份独立快照，耗时的匹配和拟合在单个后台 worker 中完成；worker 忙时不构建新快照，没有 RGB 等待队列。构建快照仍有主线程复制图像和几何筛选的开销，后台计算也会共享 CPU，尚未实测耗时。

全部相机通过检查后，主线程在下一次视觉处理开始、转换该组相机图像之前一次性安装权重；仅后续转换的图像和新生成的观测使用新权重。成功日志和各相机权重为绿色加粗。样本不足或拟合未通过时继续原灰度，并在至少一秒后尝试新快照；数据等待原因最多每五秒输出一次。依赖或配置不支持、启动异常或结果安装失败会终止校准并明确报告，主流程仍继续。

按用户要求，不清空地图、不重建或回算旧参考、不新增观测版本筛选。旧观测继续按原有选择与维护规则存在，因此切换后可能出现新灰度图像与旧灰度参考的匹配；原曝光标量不能一般性消除通道权重改变造成的差异。此过渡效果未经运行验证。权重只安装一次，曝光状态、初值、协方差和过程噪声均保持原流程。

进程退出时通知 worker 取消，并安全回收线程。正在执行的单次 OpenCV 调用不能强制中断；取消标志在调用之间检查。

## 估计的对象

相机 0 保持原 OpenCV 灰度定义，作为相对颜色响应的基准。对于待校准相机，用一组同步图像中的对应 RGB 样本拟合：

\[
 y_i \simeq \boldsymbol\beta_c^T\mathbf{RGB}_{c,i},\qquad
 \mathbf w_c = \frac{\boldsymbol\beta_c}{\mathbf1^T\boldsymbol\beta_c}.
\]

`beta` 的整体幅度只用于拟合时容纳不同曝光。函数只输出归一化后的 `w`，不保存额外增益，不把这个幅度写入原曝光状态。每个在线相机曝光参数仍按原有流程估计。

拟合采用按区域平衡的 Huber IRLS。整个物理区域划入训练或验证集合；同一次拟合中，两侧原图支撑重叠的区域不会重复计入，不能把同一个小块的像素拆成伪独立验证。检查包括颜色矩阵的秩、目标灰度变化、非负权重和独立区域误差；负系数不会被裁剪后冒充有效结果。

验证基线是“默认 RGB 权重 + 训练区域拟合的临时标量”，而不是强迫原始灰度值直接相等。若默认权重已获得足够支持且没有明确改善，则保留原 OpenCV 转换。满足无噪声线性关系、采样正确且颜色满秩时，拟合可以恢复真实通道比例；真实 RGB 含噪、非线性 ISP 或模型不适用时，没有无偏保证。

当前工程验收条件包括至少 6 个独立区域、64 个样本，验证 RMSE 不高于 5 个灰度级，以及通常至少 0.5 灰度级且 5% 的基线改善。无噪声精确恢复使用单独的数值容差判断。这些阈值尚未经用户数据集调优，不是统计置信度保证。

## 对应和取样

1. 复用当前相机模型、状态中的几何变换、LiDAR 点与已有平面关联，复制候选平面的几何值。worker 不引用实时地图或状态。
2. 在候选平面投影附近的实际输入图像裁剪区域中提取 SIFT。不会在原来仅比 patch 大一圈的小虚拟图像中强行寻找特征，也不放大正常跟踪的虚拟图像。
3. 将匹配坐标映射到局部切平面，以平面诱导单应为几何初值，再估计局部残余仿射变换。这个修正只用于初始化取样，不更新全局外参。
4. 使用双向匹配、分布检查、独立几何留出点和正反向一致性筛选局部对应。两边在共同切平面网格取样，进行有限尺度的预滤波与局部平滑，排除饱和、支撑不足和颜色变化过强的样本。
5. 有效对应交给权重拟合。相机可以沿成功的共视连接逐个校准；每台新相机的一次拟合只使用一台已经校准的父相机，不混合不同父相机的亮度尺度。必须全部成功才安装。

平面的 `radius_` 来自点分布协方差，候选支撑复用已有的半径倍数规则；它不是真实表面边界或无遮挡证明。局部滤波是保守近似，不是相机 PSF 标定。SIFT 也不保证鱼眼与针孔之间每个区域都能匹配成功。

## 存储与正常运行

初始化期间只保留当前 worker 的独立 BGR 快照、相机模型副本和有限平面候选。没有为历史 Feature 或 Observation 增加 RGB 字段。初始化结束后，仅保留每相机三个权重及转换查找表；正常图像依然输出 `CV_8UC1`，已有切平面采样、warp、残差和参考维护继续使用灰度。

当前上限为 24 个候选平面、每对相机最多处理 12 个区域、每个原图裁剪不超过 `320×320`、每相机 SIFT 输入总面积不超过 `12×320×320`、每裁剪最多 500 个特征以及每对最多 4096 个颜色样本。关键点和描述子在同一快照的共视连接之间复用，不保存 SIFT 金字塔。灰度查找表约 6 KiB/相机；实际耗时和峰值内存尚未测量。

运行日志使用 `[ Color Gray Init ]` 前缀，给出 SIFT 后端、数据等待原因、后台尝试、成功权重、共视父相机、区域/样本数、验证误差和基线误差，或者具体拒绝原因。日志中的误差包含拟合阶段的临时亮度比例，不能解释为安装权重后的原始灰度已绝对相等。

## 本次验证边界

按用户要求，本地没有编译、没有运行测试或数据集。已添加独立数学和灰度转换测试源文件并接入 `tests/CMakeLists.txt`，它们尚未执行。当前交付是代码实现与静态审查，不代表已通过目标 ROS/OpenCV 环境编译，也不代表已确认初始化成功率、耗时或里程计精度收益。

固定线性权重不能保证任意异源相机的颜色响应可统一，也不能补偿后续任意白平衡/色调映射变化。当前没有在安装时重新核验最新帧的白平衡；即使变化发生在异步初始化期间，快照上验证的权重也可能已经不适合最新图像。纯标量变化仍由原曝光模型处理；原系统历史参考的亮度基准若不一致，本模块不会回头重标定它们。初始化拟合误差也不能代替实际 8 位灰度、视觉残差和轨迹精度的端到端验证。
