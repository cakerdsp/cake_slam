模块契约表（需事先声明）

1) 全局坐标系与外参链
- 坐标系: map, odom, body(imu), lidar, cam
- 方向: 明确固定链路 body(imu)->lidar, body(imu)->cam
- base_link: 可不单独定义，默认与 imu/body 同义
- 时间约定: 所有变换按传感器时间戳求值
- 位姿状态: 以 imu/body 为主体坐标系，需明确

2) 时间与同步策略
- 必要时间戳: IMU（高频）、LiDAR 扫描（起止或逐点时间）、图像（曝光起始或中值）
- 同步策略: 队列+插值；明确可接受最大时间差（ms）
- 滚动快门与时间延迟（TD）: 是否启用及参数命名

3) 状态向量契约（融合核心）
- 最小状态: R, p, v, ba, bg
- 可选状态: 相机-雷达外参、时间延迟
- 输出: pose（map/odom -> base_link）+ 协方差 + 速度 + 偏置

4) 量测契约
- IMU: 线加速度、角速度、协方差（或统一噪声常量）
- LiDAR: 点云 + 去畸变所需逐点时间；frame id
- 图像: 单目或双目、编码、相机模型 id

5) 路标点/深度契约
- 路标表示: 逆深度或欧式坐标
- 初始化来源: 雷达深度或三角化
- 深度有效性: 距离上下限、置信度或状态标记

6) 优化契约（视觉后端）
- 滑窗大小、边缘化规则
- 残差类型: 重投影、IMU 预积分、先验
- 权重: 噪声参数集中管理，并与 IMU/LiDAR 一致

7) 数据流与所有权
- 缓存归属: 前端跟踪器或融合核心
- 关键帧与关键点输出责任
- 线程模型: 单线程或多线程（含锁）

8) 参数与配置
- 统一参数文件命名与映射
- 话题名与 frame id 在单一配置中固定


模块对照表（按项目）

FAST-LIVO2（ROS2）
- 融合核心: 基于 IESKF 的 LiDAR-IMU-Visual 里程计（主循环）
- LiDAR 预处理: 扫描去畸变 + 特征处理（preprocess）
- 地图/体素: voxel_map + 地图更新
- 视觉更新: 稀疏直接法视觉约束（LIVMapper 内）
- 参数: config/ 下 yaml + ROS2 launch

VINS-Fusion-ROS2（ROS2）
- 视觉前端: 特征跟踪与外点剔除
- 视觉后端: 滑动窗口 + 因子图（Ceres）
- IMU: 视觉估计器内部预积分
- 路标: 逆深度 + 三角化初始化
- 参数: yaml 配置 + ROS2 run/launch

LVI-SAM（ROS1）
- 视觉前端: 特征跟踪 + 掩膜 + 去畸变
- 视觉后端: VINS-Mono 风格滑窗 + 边缘化
- 雷达深度注入: DepthRegister 将点云深度赋给视觉特征
- LiDAR-IMU 后端: LIO-SAM 风格 + GTSAM 平滑
- 参数: yaml 配置 + ROS1 launch


关键差异说明
- FAST-LIVO2 使用 IESKF 进行 LiDAR-IMU；VINS/LVI 的视觉后端是滑窗优化。
- LVI-SAM 提供“雷达深度到视觉特征”的完整路径（DepthRegister），但为 ROS1。
- VINS-Fusion-ROS2 与 ROS2 集成最接近，但默认仍以视觉三角化初始化为主。


坐标系与全局原点（按项目）
- FAST-LIVO2: 使用 world/map 语义的全局坐标；状态默认 rot=I, pos=0，隐含“初始帧为全局原点”。
- VINS-Fusion-ROS2: world/body/camera frame id 由配置项指定；状态清零 + 初始化时保持初始位姿为原点。
- LVI-SAM: 视觉/回环部分使用 vins_world 与 vins_body_ros 作为世界与机体系命名；初始位姿为原点。






思路：
雷达有点 -> 投影到图像 -> 赋予深度 -> 参与优化
