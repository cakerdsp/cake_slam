选择预遍历耗时中位数 297.32 ms，范围 242.31–334.39 ms。所提供阶段都显示 `updated`，没有 LIO 无匹配/求解拒绝的证据。视觉产生更大的修正，但缺少真值且存在堆损坏，不能仅据此断言视觉权重就是漂移根因。

日志末尾为 `double free or corruption (out)`。代码中确认的问题：

1. `update_flag` 原先按 `ctx.length`（栅格数）分配，实际按观测槽位下标访问。多点/多参考候选可以突破这个上限。现按 `ctx.total_points` 分配，读写使用边界检查，并核对槽位向量长度。
2. 同一地图点可出现多个参考槽位，旧后处理会重复维护参考银行。现同一点在每个相机内维护一次。
3. 各相机的子地图借用 `Feature*`，旧后处理可以在其他相机/调试绘图使用完之前立即删除参考。现延迟到全部消费者结束后释放，并跳过已标记删除的参考。

这些是确认的代码缺陷；日志没有 ASan 栈，不能声称已证明退出时堆损坏只有一个来源。关闭选择器的漂移尚无对应运行日志可作归因。

性能修改保持 600/150/9600 的配置预算及共享误差评分模型：缓存实际共享源的交叉协方差；对零 Jacobian 列做精确边缘化并恢复完整后验；先投影再构造像素噪声列；在地图管理关闭的评分阶段跳过不用的滤波似然；跨迭代复用帧内不变的参考/地图点协方差平方根；OpenMP 可用时并行计算候选分数，按原索引顺序归约。没有引入近似贪心或将共享误差关闭。

`[ PHOTO SELECT ]` 新增 `build_ms`、`choose_ms`、`score_evals`、`state_dim`、`shared_blocks`。原 `[ VIO ] ... observations` 实际打印的是视觉体素数，现明确改为 `map_voxels`，另打印真实 `observation_slots`。

验证：11 项独立 NumPy 数值检查通过，包含边缘化/完整后验恢复、像素投影次序、共享源稀疏缓存的等价性。C++ 稠密协方差对照测试及独立性能基准已补充，但未编译运行；OpenMP 路径未做运行验证。未执行 ROS 回放。下一次需要在相同数据和配置上分别检查 ON/OFF 轨迹、退出是否正常，以及整帧耗时，而非仅看选择器的耗时。

## 诊断配置

在实际加载的 YAML 的 `debug` 下设置：

```yaml
debug:
  estimator_en: true
```

仓库的 `mid360_mei_multi_cam.yaml` 已打开此诊断。其他配置未提供此项时默认关闭。运行算法的参数、输出位姿和 NEES 评估文件格式未改动。

重新编译后启动时会打印 `[ EST CONFIG ]`：包含编译时间、ROS 参数命名空间和 VIOManager 实际使用的开关及噪声值。检查 `img=1`、`selection=0/1` 和 `trace_en=1`，并保留该整行。编译时间标识该日志所在编译单元，不是所有库一致性的验证。

每次实际执行 LIO/VIO 后打印 `[ EST STEP ]`：

| 字段 | 含义 |
|---|---|
| `status` | 更新成功、无匹配、求解被拒绝或没有生效更新等 |
| `used_residuals` | 最后保留的求解所用残差行数；不累加选择器评分、历次迭代和撤销的更新。不是独立观测数或信息秩 |
| `dp_m` / `dR_deg` | 此阶段输入到输出的平移/旋转修正范数 |
| `dv_mps` | 此阶段的速度修正范数 |
| `sigma_p_m` / `sigma_R_deg` | 此阶段输入到输出的三轴边缘标准差 RMS，即 `sqrt(trace(P_block)/3)` |
| `ms` | LIO 为建图初始化/配准调用耗时；VIO 为视觉前端调用耗时，两者统计范围不同 |

LIO 与紧随其后的 VIO 使用相同的更新时间戳，便于成对检查。`map_init` 表示首帧建图，不进行自匹配滤波更新。诊断只读取状态，不做门控、限幅或协方差缩放。

优先保存选择器关闭、能复现漂移的短片段：启动配置、漂移前后连续的 LIO/VIO 行，以及原有 `[ COV LIO ]` / `[ COV VIO ]` 拒绝原因。LIO 显示更新成功且视觉修正持续偏大时，再检查图像约束；LIO 持续 `no_matches` 或 `*_rejected` 时，应先排查雷达链路。修正范数和标准差本身不能证明某次更新错误，仍需结合轨迹及场景。

首轮诊断只增加日志；本轮修复及数值检查见上文。C++ 编译和数据回放仍待在运行环境中完成。
