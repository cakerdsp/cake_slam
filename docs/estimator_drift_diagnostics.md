# LIVO 漂移定位

本次针对 `photometric_selection_en` 开关两种状态都出现漂移的报告，补充运行诊断。当前尚未复现漂移，也未确认根因；这些输出不构成已修复的证明。

## 当前代码核对结果

- 对比 `c11c818` 与其父版本，MEI 配置的 `img_point_cov`、跨相机当前帧残差开关没有改变。
- 选择器关闭时，LIO 与 VIO 的信息矩阵/梯度权重及求解公式仍对应替换前关闭方向门控的路径。没有找到直接增大视觉权重的修改。
- 选择器开启会改变候选参考、观测集合和处理耗时，需要单独验证；这不足以解释已确认关闭选择器后的漂移。
- 更早的 `a4bdf32` 改动过实际 LIO/VIO 协方差和似然计算。比较时需要保留准确的版本号和实际运行配置。

## 诊断配置

在实际加载的 YAML 的 `debug` 下设置：

```yaml
debug:
  estimator_en: true
```

仓库的 `mid360_mei_multi_cam.yaml` 已打开此诊断。其他配置未提供此项时默认关闭。运行算法的参数、输出位姿和 NEES 评估文件格式未改动。

重新编译后启动时会打印 `[ EST CONFIG ]`：包含编译时间、ROS 参数命名空间和 VIOManager 实际使用的开关及噪声值。检查 `img=1`、`selection=0/1` 和 `trace_en=1`，并保留该整行。编译时间标识该日志所在编译单元，不是所有库一致性的验证。

每次实际执行 LIO/VIO 后打印 `[ EST STEP ]`：

| 字段 | 含义 |
|---|---|
| `status` | 更新成功、无匹配、求解被拒绝或没有生效更新等 |
| `used_residuals` | 最后保留的求解所用残差行数；不累加选择器评分、历次迭代和撤销的更新。不是独立观测数或信息秩 |
| `dp_m` / `dR_deg` | 此阶段输入到输出的平移/旋转修正范数 |
| `dv_mps` | 此阶段的速度修正范数 |
| `sigma_p_m` / `sigma_R_deg` | 此阶段输入到输出的三轴边缘标准差 RMS，即 `sqrt(trace(P_block)/3)` |
| `ms` | LIO 为建图初始化/配准调用耗时；VIO 为视觉前端调用耗时，两者统计范围不同 |

LIO 与紧随其后的 VIO 使用相同的更新时间戳，便于成对检查。`map_init` 表示首帧建图，不进行自匹配滤波更新。诊断只读取状态，不做门控、限幅或协方差缩放。

优先保存选择器关闭、能复现漂移的短片段：启动配置、漂移前后连续的 LIO/VIO 行，以及原有 `[ COV LIO ]` / `[ COV VIO ]` 拒绝原因。LIO 显示更新成功且视觉修正持续偏大时，再检查图像约束；LIO 持续 `no_matches` 或 `*_rejected` 时，应先排查雷达链路。修正范数和标准差本身不能证明某次更新错误，仍需结合轨迹及场景。
