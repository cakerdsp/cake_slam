# 自适应虚拟 patch 采样

## 开关和测试范围

三份多相机配置已登记同一个开关，默认关闭：

```yaml
vio:
  virtual_adaptive_sampling_en: true
```

- `config/HILTI22_multi_cam.yaml`
- `config/M2DGR_multi_cam.yaml`
- `config/mid360_mei_multi_cam.yaml`

设置为 `false` 或不写该键，保持原采样、参考维护、残差与更新路径。
关闭时不创建新图像金字塔，不保留新增的原图 ROI，不执行尺度参考管理。
该参数在启动时读取；比较两组结果需要分别重启节点。

本次仅修改源码、配置和测试源码，未编译、未运行、未远程部署。

## 解决的问题

前后运动可能使参考与当前图像中同一物体的像素尺度变化，而视线方向几乎不变。
仿射变换能够对齐局部几何，但固定采样间隔和未经预滤波的重采样仍可能比较不同细节尺度。
本实现按每对 patch 的局部投影选择采样间隔，并在原图采样之前滤波。
每层仍使用原来的 patch 像素数，不增大观测矩阵维度。

它不是动态物体检测器，也不把低信息方向当作异常方向。现有光度门限、ZNCC、鲁棒核和 ESIKF 保持各自职责。

## 坐标和滤波

`virtual_focal_length` 保留为标准虚拟坐标系的焦距。设：

- `D_ref, D_cur`：原有相机模型投影 Jacobian 乘切平面旋转，得到标准虚拟坐标到原图像素的局部导数。
- `A`：复用现有平面/深度仿射变换，按参考层级 0 计算标准坐标之间的映射。
- `B_ref = D_ref * inverse(A)`，`B_cur = D_cur`：共同当前坐标到两张原图的导数。

采样间隔 `h` 使用两侧原像素映射到共同坐标后的最大主轴长度，限制在 `[0.25, 4]`。
每个 solver 层的间隔为 `h * 2^level`。不再叠加旧的 determinant-based `search_level`，避免把缩放计算两次。
`f0 / h` 可以理解为该层的有效虚拟焦距，但不修改相机标定或全局投影函数。

`virtual_sampling::makePlan` 用原像素标准差约 `0.5 px` 的局部高斯模型，选择两侧均可支持的目标带宽；
按各原图局部最大奇异值换算所需的额外滤波尺度。
各向异性较强时为保守的标量近似，不是精确的椭圆滤波。

实际滤波复用 `cv::pyrDown`，其原像素累计方差为 `(4^level - 1) / 3`。
连续尺度通过相邻层按方差混合实现。**这是名义方差匹配，不等于精确高斯卷积或严格相同 PSF**；
层间插值、像素相位和镜头实际模糊仍会影响频率响应。
数学 helper 的 `0.1` 为理想高斯模型的 Nyquist 目标，不是实际金字塔频率响应的保证。
已在原图中产生的混叠不能恢复。

默认像素模糊、间隔范围和带宽目标是工程选择，并非从标定中唯一确定的常数。
标定提供局部投影尺度，仍需实验检验这些近似对误差、稳定性和耗时的影响。

## 与现有流程的衔接

1. 在观测收集阶段确定参考、仿射变换、采样间隔及每层滤波图，固定到本次迭代结束。
2. 当前 patch 复用虚拟 support 存储和插值；参考 patch 从保留的原图 ROI 按原仿射变换采样。
3. 光度梯度还原为标准虚拟坐标单位；参考不确定性 Jacobian 同步使用实际采样间隔。
4. 当前帧跨相机约束有各自的成对 support，不修改其他约束共用的历史 track support。
5. 不能完整构造采样及梯度支持时，整对回退原有采样；不单独以尺度过大为由删除观测。

参考管理复用现有相机位置与地标位置，无需再维护一份距离状态。
在已有 managed-reference 流程中，补入对称距离比例覆盖：距离相差超过约 `sqrt(2)` 时，不再仅凭相近视角认为已覆盖。
选择、生成和容量内保留参考均考虑此维度，仍服从现有地图开关、shadow 模式和容量上限。
**HILTI 配置目前 `visual_map_manage_shadow_en: true`，因此采样会生效，距离参考维护仍服从已有 shadow 规则。**
本次没有替用户改动该规则。

采样滤波会改变像素噪声及相关性；本次复用现有测量噪声模型，没有宣称新的 `R` 或 NIS 已精确校准。
需要一起观察参考接纳率，避免把滤波后的残差降低直接解释成定位精度提高。

## 支持范围和资源

首版支持当前三份配置采用的 `virtual_fisheye_patch_en=true`、`pull_exact`、`bilinear`、dense support、forward update。
与 sparse support、S2、inverse composition、其他插值模式或 `ref_patch_dump_en` 同时开启会明确报错，不会静默切换算法。
普通 `runtime_support_dump_en` 可用，adaptive 导出附带 `_sampling.txt`，参考图输出实际滤波后的 warped core。

- 每个相机当前帧共享一套按需构建的金字塔，最多 level 5。
- 每个保留参考只保存有限原图 ROI，使用时才创建其金字塔；随参考删除释放。
- 新增 ROI 扩展通常不超过 `256 x 256`；若旧 support 本身更大，保留旧范围，不裁掉原算法需要的像素。
- ROI 原点按 32 像素对齐，保持局部和整图金字塔同相位。
- 不使用依赖 ROI/图像边缘反射填充的滤波样本。
- 每层 support 只在观测收集时建立，迭代内只做现有类型的查值和梯度计算。
- 没开启当前帧跨相机约束时，成功的 adaptive track 不额外构建 legacy current support。

主要新增成本为原图金字塔、参考 ROI 内存和每层 current support 构建。尚无实测耗时，不能声称可以忽略。

## 运行时检查

开启后输出：

- `[ VIO Adaptive Sampling ]`：尝试数、成功构造数、回退数、通过原有筛选的数、平均间隔、构造耗时累加。
- `[ VIO Adaptive Current Pair ]`：当前跨相机对的构造及回退统计。
- 原有 `[ VIO Virtual Timing ]`：观测收集 wall time。

`prepare_sum` 是 OpenMP 各任务耗时累加，不是整帧 wall time，不应与总耗时重复相加。
预热后比较整帧耗时分布、ATE、跟踪数量、参考接纳率和 fallback 比例；首次滤波和首次参考物化单独看。

已提供但未执行的独立测试：

- `virtual_sampling_math_test`：局部尺度、交换两侧、坐标变换、奇异输入和距离覆盖。
- `adaptive_image_pyramid_test`：坐标/梯度、方差混合、边界、ROI 同相位及并发缓存。

最终仍需在有 ROS/OpenCV 环境的电脑编译和回放同一数据，验证关闭开关与原版本一致，以及前后运动片段的收益和开销。
